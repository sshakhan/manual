# Токены

Все переменные, которые оболочка объявляет и использует, живут в `@layer
tokens` и названы `--manual-*`. Слои существуют именно для того, чтобы их
можно было безопасно перебить: **переопределяйте токен в своём `theme.css`,
без слоя** (`:root { --manual-brand: ...; }`, не `@layer чего-то`) — неслоёная
таблица стилей всегда старше любого слоя, независимо от порядка подключения и
специфичности, поэтому такое переопределение побеждает без `!important` и без
знания того, в каком порядке объявлены слои оболочки. Так делает шаблон,
который выдаёт `manual-kit new-manual` (`src/theme.css`), и так же стоит
делать в любом собственном.

Три токена — `--manual-sidebar-width`, `--manual-content-width` и
`--manual-rail-width` — объявлены через `@property` с `syntax: '<length>'`.
Это значит, что, если переопределить такой токен значением, не являющимся
длиной (опечатка, пустая строка, ключевое слово из другого набора), браузер не
подставит мусор в разметку — он откатится к начальному значению токена
(`initial-value` из `@property`) и макет останется рабочим, а не поедет.
Остальные токены такой защиты не имеют: некорректное значение цвета,
шрифта или отступа применится как есть.

## Цвет

| Токен | Значение по умолчанию | Что задаёт |
|---|---|---|
| `--manual-brand` | `oklch(60.5% 0.098 208)` | Основной акцентный цвет: активные элементы, ссылки, выделения |
| `--manual-brand-strong` | `color-mix(in oklab, var(--manual-brand) 82%, black)` | Затемнённый вариант акцента (hover/active состояния) |
| `--manual-brand-tint` | подмешивание `--manual-brand` к `--manual-surface`, доля различается между `light`/`dark` через `light-dark()` | Мягкий фон под акцентными элементами (подсветка активного пункта и т. п.) |
| `--manual-text` | `light-dark(oklch(28% 0.02 245), oklch(93% 0.01 245))` | Основной цвет текста |
| `--manual-text-muted` | `light-dark(oklch(54% 0.02 245), oklch(70% 0.015 245))` | Приглушённый текст (подписи, вспомогательные надписи) |
| `--manual-surface` | `light-dark(#fff, oklch(21% 0.012 245))` | Фон карточек и панелей переднего плана |
| `--manual-surface-alt` | `light-dark(oklch(98% 0.004 210), oklch(25% 0.014 245))` | Фон страницы/боковых зон |
| `--manual-line` | `light-dark(oklch(92% 0.008 210), oklch(32% 0.015 245))` | Цвет разделительных линий и рамок |
| `--manual-warning` | `oklch(76% 0.145 70)` | Акцент врезки `callout` варианта `warning` |
| `--manual-warning-tint` | подмешивание `--manual-warning` к `--manual-surface` | Фон врезки `warning` |
| `--manual-danger` | `oklch(60% 0.19 22)` | Акцент врезки `callout` варианта `danger` |
| `--manual-danger-tint` | подмешивание `--manual-danger` к `--manual-surface` | Фон врезки `danger` |
| `--manual-success` | `oklch(60% 0.14 145)` | Акцент врезки `callout` варианта `success` |
| `--manual-success-tint` | подмешивание `--manual-success` к `--manual-surface` | Фон врезки `success` |

Семантические цвета (`warning`, `danger`, `success`) не выводятся из
`--manual-brand` намеренно: у них своя смысловая нагрузка, и они не должны
менять оттенок вслед за брендом.

## Типографика

| Токен | Значение по умолчанию | Что задаёт |
|---|---|---|
| `--manual-font` | `'Nunito', 'Mulish', system-ui, -apple-system, 'Segoe UI', sans-serif` | Шрифт всего текста в оболочке. Шрифты не встраиваются в пакет — при сборке в один файл файл шрифта на каждое начертание раздул бы сборку; стек откатывается к системному UI-шрифту |
| `--manual-font-mono` | `ui-monospace, 'SF Mono', Menlo, monospace` | Моноширинный шрифт (например, для комбинаций клавиш в блоке `keys`) |
| `--manual-step-0` | `1rem` | Базовый размер текста (абзац) |
| `--manual-step-1` | `1.125rem` | Увеличенный текст (подзаголовок `h3` и т. п.) |
| `--manual-step-2` | `clamp(1.25rem, 1.1rem + 0.6cqi, 1.375rem)` | Заголовок `h2`, тянется от ширины контейнера |
| `--manual-step-3` | `clamp(1.5rem, 1.2rem + 1.4cqi, 1.875rem)` | Заголовок верхнего уровня (заголовок главы), тянется от ширины контейнера |
| `--manual-step-small` | `0.875rem` | Уменьшенный текст (подписи под картинками, метаданные) |
| `--manual-step-tiny` | `0.78rem` | Самый мелкий текст (сноски, лейблы) |

## Отступы

Единая шкала отступов на всю оболочку — раньше у каждого типа блока была своя
величина нижнего отступа, из-за чего вертикальный ритм зависел от того, какой
блок стоит выше. Теперь блоки берут отступы из этой шкалы.

| Токен | Значение по умолчанию | Что задаёт |
|---|---|---|
| `--manual-space-1` | `4px` | Минимальный отступ (между тесно связанными элементами) |
| `--manual-space-2` | `8px` | Малый отступ |
| `--manual-space-3` | `12px` | Средний отступ |
| `--manual-space-4` | `18px` | Отступ между блоками контента по умолчанию |
| `--manual-space-5` | `28px` | Крупный отступ (между смысловыми группами) |
| `--manual-space-6` | `40px` | Самый крупный отступ (между секциями) |

## Разметка

Три токена ниже объявлены через `@property` с `syntax: '<length>'` — см. выше
про откат к начальному значению при некорректном переопределении.

| Токен | Значение по умолчанию | Что задаёт |
|---|---|---|
| `--manual-sidebar-width` | `320px` | Ширина левой колонки (оглавление, поиск, переключатель языка) |
| `--manual-content-width` | `780px` | Максимальная ширина колонки с текстом главы |
| `--manual-rail-width` | `240px` | Ширина правой колонки («В этом разделе») |

## Радиус

| Токен | Значение по умолчанию | Что задаёт |
|---|---|---|
| `--manual-radius` | `6px` | Скругление мелких элементов: кнопок, полей поиска, ячеек |
| `--manual-radius-lg` | `12px` | Скругление крупных элементов: карточек, врезок, изображений |

## Точки перелома

| Токен | Значение по умолчанию | Что задаёт |
|---|---|---|
| `--manual-breakpoint-narrow` | `900px` | Ширина, ниже которой оболочка переходит в одноколоночную раскладку и скрывает правую колонку за переключателем |
| `--manual-breakpoint-wide` | `1200px` | Ширина, ниже которой скрывается правая колонка «В этом разделе», но боковое меню остаётся видимым |

Раскладка переключается через `@container` по ширине `.manual` (контейнерные
запросы), а не по ширине окна, — поэтому оболочка одинаково ведёт себя и на
всю ширину экрана, и встроенной в более узкую колонку хост-приложения.

На момент написания сами условия `@container` в `manual.css` захардкожены
числом (`900px`, `1200px`), а не читают эти токены через `var(...)` — значения
совпадают, но переопределение токена в `theme.css` **не изменит** точку
перелома в текущей версии пакета. Токены документируют точки перелома, а не
управляют ими; знать это стоит прежде, чем тратить время на отладку
переопределения, которое не сработает.
